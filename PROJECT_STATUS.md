# langLSRW Project Status

Last updated: 2026-09-28

Detailed behavior, storage, synchronization, and build rules are maintained in [`MECHANISMS.md`](MECHANISMS.md). The accepted multi-language adapter direction, including future German and French packages, is documented in [`MULTILINGUAL_ARCHITECTURE.md`](MULTILINGUAL_ARCHITECTURE.md). Spanish is the first additional language and is now in early implementation; its implemented scope, remaining rollout, and linguistic risks are documented in [`SPANISH.md`](SPANISH.md). The generic adapter architecture is only partially extracted, and German and French packages are not implemented.

## Current Stage

langLSRW is currently a personal language-learning prototype in a local-first development stage. The listening and speaking workflow is usable for daily local testing. Reading, writing, broader review pools, and article generation are still future work. The production deployment is connected to Supabase, and Google login has been verified on the deployed site. The formal-release direction is cloud-first for signed-in accounts, with the cloud as authoritative cross-device storage and browser data serving as an offline cache; explicit local-user mode will remain local-only.

Local testing remains the default development workflow. Run `tools/start-langlsrw-server.bat`, then open `http://localhost:8848/`. The source repository is connected to Vercel and the first production deployment completed successfully on 2026-09-24. Vercel hosts the frontend, while Supabase now provides Google authentication and the existing initial-sync backend. Cross-device synchronization still requires explicit end-to-end verification. Future deployments and external service changes still require the owner's explicit request.

### Local dictionary

- ECDICT's basic `ecdict.csv` is the fixed source for the initial dictionary build; the larger `stardict.7z` data is not used by the runtime build.
- The untouched ECDICT upstream source is kept outside the web repository at `../third-party/ECDICT-master/`; `ECDICT_SOURCE_DIR` can override that maintenance-time path.
- `tools/build-ecdict.py` generates the ECDICT-compatible SQLite table and indexes, validates the database, creates a deterministic gzip package, and writes a versioned manifest with entry count, sizes, and hashes.
- The current basic build contains 770,611 entries. Its SQLite database is about 170.4 MB and its gzip download package is about 67.8 MB.
- `tools/build-spanish-dictionary.py` generates the first Spanish Wiktionary package from `../third-party/Spanish/kaikki.org-dictionary-Spanish.jsonl` via `npm run build:dictionary:es`. The current Spanish build contains 770,716 entries. Its SQLite database is about 416.2 MiB (436,391,936 bytes) and its gzip download package is about 66.8 MiB (70,042,471 bytes). The package SHA-256 is `2a5f13af97f31a3b68e9c579b0ab5954446388f293e2e75d8c9e3645ee082bc6`. `tools/build-spanish-frequency.py` separately generates `frequency.tsv` (17,458 ranked lemmas) beside it from `../third-party/Spanish/frequency/frequency.csv` and records it in the manifest's `frequency` entry; the package itself is unchanged.
- `DictionaryService` exposes stable `status`, `install`, `remove`, `query`, `match`, and `count` operations with dictionary IDs. A Worker-backed SQLite adapter currently implements those operations for separate OPFS database files; a future server API/MySQL adapter can implement the same contract.
- The Settings panel displays installation state and sizes, installs the compressed package into browser OPFS, supports removal, and provides an explicit test query.
- Words in the listening source can be queried from the installed local dictionary by right-clicking; a configurable keyboard shortcut queries the current word. Results expose the metadata available from the active language's dictionary without calling AI. English lookup uses ECDICT and shows pronunciation, bilingual definitions, Collins rating, Oxford 3000 membership, study tags, corpus ranks, parsed inflections, collection stars, and mastery cards. Spanish lookup uses `spanish-wiktionary`, shows its English glosses, parsed Wiktionary inflections, subtitle-frequency rank, collection stars, and Spanish-scoped mastery cards. When an ECDICT entry for a single-`l` American `-ling`, `-led`, or `-ler` form has no inflection data, lookup checks the corresponding double-`l` spelling and reuses only its explicit `0:` lemma, which covers gaps such as `traveling -> travelling -> travel` without guessing an unverified root. The lookup popover has a `自动发音` checkbox left of the favorite area; when on (the default; the choice is saved per browser), each looked-up word is read aloud automatically.
- The base dictionary is opened read-only. User vocabulary, notes, overrides, history, and review state must remain outside the replaceable ECDICT database.
- SQLite WASM is pinned through npm and copied into static vendor assets by `tools/vendor-sqlite-wasm.mjs`; website users do not install SQLite, Python, or Node.

### Listening and dictation

- Import `.txt` and `.lrc` (text only, in the `自定义句库` panel), paste sentence lists, or use the built-in common sentence library. Audio + subtitle materials are imported only in the `音频字幕` panel or by dropping both files onto the listening page.
- Import an audio file (for example `.m4a` / `.mp3`) together with its timed `.lrc` subtitles: timed English lines are preserved as audio boundaries and continuation fragments are grouped into complete learning sentences, which play their corresponding original-recording segments for listening, replay (with speed control), the speaking model shortcut, and `原声对比`; single-word replay still uses TTS. The `句库` dialog's `音频字幕` view lists bundled materials in `assets/audio/` (default `Audio_Example.m4a` + `Audio_Example.lrc`) and imports new audio + `.lrc` pairs; `assets/audio/` is copied into the deployment build, so bundled materials are publicly downloadable once committed and deployed. Sentences without translations in `自定义句库` / `音频字幕` can be translated for free with the browser's built-in on-device Translator API (desktop Chrome/Edge 138+); results are cached locally by English text and reused on later imports. The `音频字幕` panel's `翻译字幕` picks any timed `.lrc` (no loading needed), translates it, and on a second click writes a bilingual version back to the same file (`写入原文件`), saves it as a new `<name>_双语.lrc` (`另存字幕文件`), or downloads a same-named file where the save dialog is unavailable. Download progress appears only when the translation model is not yet on the device, and cancelling the file dialog clears the status. The bundled `Audio_Example.lrc` is now bilingual (136 sentences, all translated). While audio material is loaded, the accent select defaults to `原声` and can switch to 英音 / 美音 TTS and back. The settings menu's `清除翻译缓存` empties the local translation cache without touching learning data. See `AUDIO_LRC.md` for usage, subtitle format, and limits.
- Original-audio playback keeps the 0.3-second end margin for standalone subtitle lines. Sentences assembled from multiple subtitle fragments instead end at the final fragment's real next-line boundary, preserving tightly timed last words. The audible cutoff uses a Web Audio gain schedule tied to the rendering clock, removing refresh-dependent end variation from timer polling.
- Known subtitle-data boundary: machine-generated subtitles can omit words that are present in the recording, split speech incorrectly, or place the next timestamp after those words. The bundled sample has one such case between `has the water added.` and `It's kind of clarifying`, where the recording contains `you can see` but the LRC does not record it. This is not player replay; the words' sentence ownership should be determined from the audio context before correcting the local LRC text and timestamp. Future tooling may add waveform-based per-sentence text and boundary editing.
- A second bundled-sample boundary case occurs after `cheese-making process.`: the next utterance begins before its machine-generated timestamp, so the standalone 0.3-second margin still captures a clipped onset. This requires a local timestamp/end-point correction; increasing the global margin would regress otherwise correct sentence endings.
- English source above Chinese translation, with independent source and translation visibility. The source's favorite stars sit level with its first line, and the translation (and its hidden-translation mask) ends at the star column's left edge, with the `编辑` button inside that column.
- The listening toolbar includes a persisted display-mode select before `显示原文`: `单句显示` (single sentence), `长文显示`, and `长文聚焦`. Both long-text modes expand the source area into a scrollable 15-sentence context view with smaller fonts (English 18px, translation 13px), present each sentence as English (with its favorite stars) followed by its translation, keep the current sentence's full dictation feedback, favorite, translation editing, and grammar view, and leave the dictation input sized by what has been typed. Clicking another sentence switches to it; every row shows its translation's `编辑` (and `中译` in Spanish), and using one on another row first switches to that sentence. Both keep the current sentence centred; `长文聚焦` also fades and slightly blurs the other sentences and hides their stars and translation buttons.
- Ordered, random, full-text (`全文`), and mistake practice modes, with random practice as the default. In `全文`, starting to read (the `朗读` button, its shortcut, or automatic pronunciation) reads continuously from the current sentence to the last one in library order (original audio plays as one uninterrupted stream with the practice view following it; TTS sentences follow each other without pauses), then stops; `朗读` turns into `停止 ⏹` while reading, and any navigation, stop, word replay, or library/mode change cancels it. Sentence navigation in `全文` works like ordered mode.
- Source-file import and pasted sentence input are grouped under Library > Custom Library; current-sentence translations are edited directly in the practice translation area, and AI provider settings are grouped under the global Settings menu.
- The practice toolbar always shows the active sentence-library type (`常用句库`, `自定义句库`, `用户收藏`, or `音频字幕`).
- Previous/next sentence navigation, British English as the default accent, voice selection, normal and slower replay, word replay, and automatic pronunciation on sentence change (the toolbar checkbox is labelled `自动发音`, matching the lookup popover).
- Dictation input with accuracy, speed, pause, fluency, and error statistics. The home-page dictation no longer writes practice records (it will be replaced by sentence review), so the `错句` mode currently has no data and falls back to library order; the learned count was removed.

This is separate from the disabled, permission-heavy `跟原声对比` pitch/acoustic-analysis experiment above.
- The experimental `跟原声对比` implementation is retained but its entry button is currently hidden because the feature is not mature enough for daily use. When enabled for development, it captures the TTS model reading and the learner's recording, then locally provides four switchable views: normalized relative-pitch contours (`语调`), relative-RMS emphasis curves (`重音`), voiced segments and pause counts (`节奏`), and an MFCC + constrained-DTW acoustic-difference strip (`发音对比`). Nothing is uploaded and no phoneme-level pronunciation score is produced.

### AI grammar analysis

- Manual AI trigger; sentence switching and ordinary practice never trigger paid requests. Sentences with a saved analysis show 🌈 left of the translation's `编辑`; clicking it shows or hides the analysis (on a neighbouring long-text sentence it switches there first). A running analysis stays with the sentence it was started on: the loading placeholder does not follow navigation or `全文` reading, and when the result arrives `全文` reading stops and the view returns to that sentence to show it.
- Personal local API settings stored in browser storage for the current private-use stage.
- Traditional English teaching grammar is the only enabled runtime framework.
- Hierarchical grammar JSON rendering with main, first-level, and all-node views.
- Role-specific colors, expandable nodes, notes, child indicators, and explanations. A node's role/type label is baseline-aligned with its text (not box-centered, since the label's Chinese font and the text's English font have different optical centers at the same line-height) and never wraps internally; a pure-punctuation node (matched by a Unicode-punctuation regex on its text, not by its label wording) shows no label at all. A node's own colored border is never capped by an unrelated fixed pixel width, and any clause-type node (`type` containing `从句`) always shows its role-colored top border regardless of expand state. Expanding a collapsed node always reveals exactly one level of children; any deeper descendants left expanded from an earlier interaction are collapsed first, so re-expanding a node never restores stale multi-level state.
- Cached analysis reuse for the same sentence; reanalysis is an explicit context-menu action.
- View and copy the exact AI prompt and raw/formatted AI response.
- The compact toolbar exposes only `Ai语法分析`; its context menu contains the active grammar framework, prompt/response viewing, and explicit reanalysis.
- Prompt source is maintained in the traditional grammar Skill and generated into `src/generated/grammar-prompt.js`.
- SIEG2 remains a separate Skill and appears disabled in the UI; it is not included in the active runtime prompt.

## Known Boundaries

- Reading and writing pages are not implemented yet.
- AI article generation, writing review, and review-material generation are not implemented yet.
- The `句库` picker (the dialog opened from the `句库` button) offers only the built-in common library and custom import/paste; `用户收藏` was removed from that dialog specifically. It remains reachable as `常用句库`'s sibling option in the toolbar's quick-switch dropdown, and via the `▶` button on each row in `收藏`'s `句子` tab. The other placeholder categories (情景/语法/等级/短语句库) still have no data.
- Supabase authentication, schema, and first-stage sync code are connected to the production project. Google sign-in works; cross-device state synchronization has not yet completed a two-browser or two-device verification pass. Local browser storage remains the primary offline data layer.
- Manual synchronization still uploads the complete cloud payload rather than field-level changes; large custom libraries can therefore consume substantial traffic per click. Incremental synchronization remains future work.
- The planned cloud-first account model is not implemented yet. Before formal release it still needs complete data coverage, an offline queue/cache policy, deterministic conflict handling, schema migration, retry and recovery behavior, and explicit user-visible sync status. The current whole-row manual-sync implementation must not be treated as that final architecture.
- The API key is stored in browser local storage and is acceptable only for private local use.
- Personal data was rebuilt on 2026-09-28 (`src/user-data.js`, `USER_DATA.md`): per-identity, per-language records in IndexedDB with an in-memory cache; export, import (merge by record, newer wins), user deletion, and cloud sync all follow one registry. Pre-refactor browser keys are no longer read and were not migrated (debug-stage decision). Remaining boundaries: cloud upload still replaces the whole row without comparing timestamps; import has no full-replace option; invalid sentence favorites (library changed) are hidden without a count; custom libraries are not stored; answer records (`practiceEvent`, `reviewEvent`) are disabled until a feature uses them.
- Before public AI access, requests must move behind a backend proxy with quotas and cost controls.
- Speech recognition and recording depend on browser support and microphone permission.
- The disabled `跟原声对比` experiment depends on browser tab/system-audio capture. Its current sharing request is intentionally the minimal Edge-compatible `getDisplayMedia({ video: true, audio: true })`; when development testing resumes, the learner must select the current tab and enable audio in the browser's system dialog. Other browsers and operating systems remain compatibility-test targets.
- The local `发音对比` view visualizes broad MFCC/DTW acoustic differences only. It does not locate incorrect phonemes or words, judge accent correctness, or produce a pronunciation score.
- The native system color-picker dialog cannot be customized by the webpage; HEX editing is provided in the settings panel.
- The uncompressed generated SQLite file is intentionally discarded after packaging. The versioned gzip package is the runtime asset; raw CSV sources and development tools must not enter the website deployment.
- Browser dictionary installation requires OPFS, Web Workers, WebAssembly, streaming fetch, and gzip `DecompressionStream`. Current Chromium verification passes; Firefox and Safari remain explicit compatibility-test targets.
- Supabase provisioning, Google OAuth provider configuration, `supabase/schema.sql`, production redirect URLs, and Vercel public environment variables are configured. Any additional deployment domain must also be added to Supabase Auth redirect URLs before Google login can return to it.
- `dist/` is generated output and is ignored by Git. Vercel provides `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` together during production builds; neither the Google OAuth client secret nor any Supabase secret/service-role key belongs in frontend or Vercel public build configuration.
- Clearing browser site data removes the installed local dictionary. It can be reinstalled without affecting the source package.
- Imported audio for audio + LRC materials is held only in memory; after a page reload both files must be imported again. Sentence boundaries come only from subtitle timing: lines are capped at 2.5 s + 0.6 s per word and split sentences are merged by punctuation and case heuristics, so irregular subtitles may still merge imperfectly.
