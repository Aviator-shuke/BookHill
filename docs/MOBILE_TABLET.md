# 手机与平板兼容

状态：**基础手机显示适配已实现，触屏专属交互待完善**。最后更新：2026-10-20

本文档记录 langLSRW 在手机、平板上的实际适配范围和剩余兼容计划。已在 Edge 设备模拟中检查基础布局；尚未完成 iPhone Safari、Android Chrome 和 iPad Safari 真机验证。

## 1. 目标与原则

- 触屏设备（手机、平板）上，听、说、读、写、收藏、词库、背单词、设置都能完成日常学习，不依赖鼠标悬停、右键和键盘快捷键。
- 只在必要处调整交互，不为触屏另做一套页面；仍遵守 `AGENTS.md` 的“四个学习页面各自独立”原则。
- 电脑端的体验不因兼容而变差：悬停提示、快捷键、右键等电脑端功能保留，触屏上给出等价的操作方式。

## 2. 现状

- 页面设置设备宽度、安全区域和支持浏览器的软键盘视口缩放；弹窗使用动态视口高度。700 像素以内或 900 像素以内且高度不超过 500 像素时启用手机布局，句子工具栏在 1100 像素以内换行。
- 手机主页使用紧凑导航、换行工具栏和单列听说区域；词库、收藏和设置把分类放在顶部，列表 / 设置项和详情上下排列，分别滚动。较矮视口改为整体滚动，避免下部内容被截断。窄屏取消词库和收藏的拖动调整大小。
- 手机顶部为两行：品牌 / 语言 / 学习页一行，词库 / 句库 / 收藏 / 护眼 / 设置 / 用户一行。电脑端功能入口使用相同顺序；主题按钮文字仍随当前主题变化。“用户”保留原用户名文本作为无障碍名称，桌面显示完整用户名。手机工具栏统一使用 13 像素文字、28 像素控件高度，顶部功能入口高 32 像素；减少卡片间距和装饰性边框，语速标签与数值始终同组。
- 句子工具栏压缩为三行：句库 / 模式 / 上下句 / 显示方式，原文 / 翻译 / 自动发音 / 朗读 / 口音，声音 / 倍速 / AI语法 / 序号 / 帮助。选择框使用紧凑宽度，不整行拉伸；省略“句库 / 语速”重复标签，手机语法按钮简写为“AI语法”，操作说明保留。容器在桌面使用 `display: contents` 保留原有横排及完整标签。320、390、474、700 和 1440 像素下检查无控件横向溢出，四位序号仍能同排；手机工具栏实测高 92 像素；文字、选择框、按钮和数字统一为 13 像素，行距 4 像素，序号紧接操作按钮，取消重复的微型序号步进按钮。
- 设置说明在手机默认收起，可点击标题栏“说明”展开；桌面仍显示右侧说明栏。手机端隐藏词库 / 收藏的“恢复默认大小”，词表翻页按钮增大为 32 像素，弹窗打开时限制背景页面滚动。
- 词库和收藏列表通过共享 `bindTouchWordSelection()` 明确处理触屏点击，星级和进度按钮保留各自行为；桌面鼠标仍使用原有悬停与焦点选择。答题反馈面板在手机布局内提供独立“下一个”按钮，复用现有队列动作；桌面不显示这个附加按钮。
- 答题反馈继续覆盖在主弹窗右侧，主弹窗不因结果出现改变位置或尺寸。其他表单的输入框和选择框使用至少 16 像素字体；句子工具栏为统一视觉使用 13 像素，iOS 真机聚焦缩放仍待验证；按住说话按钮禁用触摸滚动和文字选择。
- 布局验证覆盖 320×740、390×844、430×932、844×390、768×1024 和 1440×900；检查主页及设置、句库、词库、收藏弹窗，无页面横向溢出和脚本异常。测试使用独立浏览器上下文的临时本机用户；词典未安装，未验证真实词典列表和手机语音能力。
- 320 像素下检查登录卡片和全部八个设置分类，无内部横向溢出。用临时单词数据检查反馈面板：主弹窗答题前后均为 374×272 像素且坐标不变，结果覆盖右侧；390×380 的缩小视口下弹窗仍位于可视区域。该检查用于布局，不替代实际词典复习和真机软键盘测试。
- 所有说明性文字都靠悬停显示（`title` 由共享提示框接管，见 `MECHANISMS.md`）。共享提示框明确不响应触摸输入。

以下清单保留触屏交互的原始问题及候选方案；M7 工具栏、M10 窄屏尺寸、M11 多列挤压已有上述显示适配，完整触屏操作及真机检查仍待完成。

后续验证补充：Edge 触屏模拟中通过设置说明展开 / 收起、临时词典数据的点击选词、结果侧栏“下一个”推进队列；结果出现前后主弹窗坐标和尺寸不变。桌面宽屏隐藏手机附加按钮并保留右侧设置说明；M8 / M9 的单词点击已实现，收藏句子翻译等其他悬停交互仍待完善。

## 3. 已知不兼容点（待处理清单）

### Android 实机对照检查

所有者已确认 Android Edge / Chrome 都有“录音能回放、识别无文字”，桌面识别正常。不能仅凭这个现象认定录音争用或浏览器不支持。使用独立页面 `/src/diagnostics/speech.html` 对照，不修改主页的按住交互和录音能力：

1. 首次允许麦克风后，先按住“只识别”约 5 秒，说一句英语，再松开；重复一次。
2. 按住“识别＋录音”说相同句子，也重复一次。此模式使用与主页相同的识别、录音双路启动顺序。
3. 复制诊断记录。若只有第一项有字，支持并发兼容问题的方向；两项都无字则需检查识别服务、系统支持、网络和错误事件，不能直接归因于并发。

页面不加载用户数据、不永久保存结果、不增加收费接口；浏览器自身识别服务的音频处理方式保持原样。导出只包含浏览器标识、能力、事件时间、结果字符数和录音字节数，不含录音及原话。离开页面会中止识别、结束录音并释放麦克风。新增页面需经所有者授权部署后才能通过线上地址在手机访问；本次未部署。

主页语音反馈已修复：错误信息不再被 `renderSpeakingPage()` 清除；空识别结果不覆盖已有文字；没有文字的会话结束时显示提示。390×844 Edge 模拟的实际触摸按下 / 松开已触发浏览器识别和录音，但该次返回空文字；真实手机讲话转字仍待验证。非空结果显示、错误保留及旧会话回调隔离另用受控事件检查通过。

M6 的长按菜单已有防护：共享捕获监听处理 `.hold-speak-button` 的 `contextmenu`，主页及动态单词练习按钮均适用；触屏样式补充 `-webkit-touch-callout: none`。受控事件检查通过，但所有者实际浏览器仍报告菜单弹出，尚不能标记为已解决。手机和电脑继续保持按住开始、松开结束。

松手阶段补充：保护范围包含整次按住手势及松手后 800 毫秒、48 像素内的菜单，解决菜单目标不再是按钮时的遗漏；非被动 touch 监听只取消由说话按钮开始的原生手势。Edge 模拟实际触摸仍能正常触发识别 / 录音，外层目标的松手菜单测试通过；范围外及时间过后的右键保留。

M14 的音频生命周期补齐：`renderSpeakingPage()` 在识别期间不修改回放元素的 `src`，识别结束后仅在 URL 变化时挂载；不再反复写入空 `src`。开始说话先停止范读及回放。此修改不取消录音、不改变按住操作，也不改用外部转写服务。已验证 DOM 音源变更次数和启动先后顺序，真机的识别 / 录音并发兼容性仍待验证；当前截图不足以确定浏览器内核或排除识别服务本身的问题。

## 4. 初步实现思路

- 用 `@media (pointer: coarse)` 和 `@media (hover: none)` 区分触屏，不用屏幕宽度判断设备。窄的电脑窗口仍然按电脑处理。
- 先做“不能用”的功能（M2、M3、M4、M7），再做“不好用”的（M10、M11、M16）。
- 长按的公共处理写成一处共享逻辑，右键查词、语法菜单等都复用，不要各页各写一套。
- 真机测试至少覆盖：iPhone Safari、Android Chrome、iPad Safari。电脑上的窗口缩放和设备模拟只能验证布局，不能验证长按、软键盘和语音权限。

## 5. 待定

1. 支持的最低屏幕宽度（例如 360 像素）。
2. 手机上是否保留全部功能，还是先保证 `听`、`说`、`背单词` 三条主线。
3. 长按的时长和反馈方式（震动、动画）。
4. 是否需要把网页做成可安装应用（PWA），以便离线使用和更好的全屏体验；这属于部署方向，需要 owner 决定。
